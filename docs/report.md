# CardioMap — Technical Report (Track A)

**Multimodal AI Hackathon 2026** · Track A: Cardiovascular Risk Visualization & Prediction  
**Author:** Solo submission · **Dataset:** Extension of Z-Alizadeh Sani (UCI ID 411, n=303)

---

## 1. Problem statement

Coronary artery disease (CAD) risk is often communicated as opaque percentages. Clinicians and patients benefit from (1) **where** stenosis is predicted along the **LAD**, **LCX**, and **RCA**, and (2) **why** the model assigned that risk from clinical measurements. CardioMap combines multi-target classification, SHAP-based explanations, and an interactive 3D schematic heart driven by live model outputs.

**Scope:** Educational / decision-support prototype only — not a diagnostic device.

## 3. Modeling methodology

1. **Preprocessing:** median imputation + standard scaling (numeric); one-hot encoding (categorical). Fitted once; serialized as `models/preprocess.joblib`.
2. **Candidates (per target):** L2 logistic regression (balanced), random forest (300 trees, balanced), LightGBM (balanced).
3. **Selection:** Repeated stratified **5-fold CV × 3 repeats**; choose model with highest **mean ROC-AUC**; refit on all 303 rows for deployment.
4. **Deployment artifacts:** `models/cath.joblib`, `lad.joblib`, `lcx.joblib`, `rca.joblib`, plus `metrics.json`.

**Note:** Full-training metrics show high fit (small tabular set + tree models). **Judging emphasis is on cross-validation** below, not train-set accuracy.

## 4. Explainability (SHAP)

For each prediction, TreeExplainer or LinearExplainer runs on the transformed feature vector. The API returns the top 10 features by |SHAP| with direction (`increases_risk` / `decreases_risk`). Global mean |SHAP| rankings are stored in `models/global_shap.json` (`python -m ml.explain`).

The dashboard links vessel selection (LAD/LCX/RCA cards or 3D tubes) to the explanation panel so spatial risk and drivers stay aligned.

---

## 5. System architecture

```
Excel dataset → preprocess.joblib → 4 classifiers → FastAPI /api/predict
                                      ↓
                         probabilities + SHAP → React UI
                                      ↓
                         R3F heart: LAD/LCX/RCA color ∝ probability
```

- **Backend:** FastAPI (`api/main.py`) — schema-driven patient form, sample records, metrics, predict.
- **Frontend:** React + Vite + React Three Fiber — 3D heart, risk summary, validation tab.
- **Run:** `run.ps1` builds UI and serves API + static frontend on port 8000.

---

## 6. 3D visualization

Schematic heart mesh with three **Catmull-Rom coronary tubes** mapped 1:1 to model outputs (`web/src/anatomy/registry.ts`). Color scale: green (low) → red (high stenosis probability). OrbitControls for rotation; clinical disclaimer always visible.

Anatomy is **educational schematic**, not patient-specific angiography.

---

## 7. Limitations and future work

- **Sample size:** n=303 limits power; CV variance is visible especially on LCX/RCA.
- **RCA recall:** OOF recall is modest; model favors precision at 0.5 threshold — threshold tuning could be clinician-guided.
- **External validity:** Not tested on other hospitals or imaging modalities.
- **Regulatory:** Not validated as a medical device; no emergency triage.

Future: segmented coronary meshes, calibration plots, prospective validation, DICOM/angiography integration (out of hackathon scope).
